# MANA XZ — решение по персональному движку и агенту разработки

Статус: архитектурное решение / реализация не считается готовой до сборки и тестов.

## 1. Два разных агента

Не смешивать:
- **MANA Brain** — конечный продукт на телефоне. Личный локально-ориентированный ИИ, который общается, планирует, использует память, инструменты и модули.
- **Development Agent** — помощник разработки, который читает репозиторий MANA, меняет исходники, запускает тесты и готовит проверяемые изменения.

Готовый coding agent не является движком MANA Brain и не должен встраиваться в APK как «мозг».

## 2. Какой редактор использовать для разработки

Основной текущий маршрут: работать с существующим GitHub-репозиторием MANA непосредственно из текущего ChatGPT-сеанса через подключённую GitHub-интеграцию и GitHub Actions. Это сохраняет единый контекст требований, уже существующие ветки/PR и CI. Изменения выполняются в рабочей ветке; main и открытые PR не сливать без отдельного разрешения владельца.

Внешние варианты:
- **OpenHands Software Agent SDK / Agent Server** — перспективный отдельный cloud/self-hosted coding-agent для больших рефакторингов, работы с GitHub, тестами и несколькими агентами. MIT. Это агент разработки, не Android inference runtime. Подключать только при наличии безопасного изолированного workspace и явных разрешений на запись.
  - https://github.com/OpenHands/software-agent-sdk
  - https://github.com/OpenHands/OpenHands
- **Cline** — автономный coding agent с IDE/CLI/desktop и human-in-the-loop approvals; полезен разработчику с компьютером, но не основной маршрут для владельца, который работает только со смартфона.
  - https://github.com/cline/cline
- Не создавать отдельный Replit-проект как замену основному Android-репозиторию: это раздвоит кодовую базу и не решит автоматически native Kotlin/NDK сборку существующего приложения.

## 3. Персональный MANA Engine 2.0

Не переписывать математику LLM inference с нуля. Создать собственную архитектуру MANA поверх проверенных inference backends:
- **MANA Brain Core (Kotlin)**: единая личность, контекст, планирование, многошаговые задачи, контроль результата, журнал и политики.
- **InferenceBackend API**: load, unload, generateStream, cancel, health, capabilities, benchmark.
- **llama.cpp / GGUF**: основной кандидат для CPU-first ARM64 профиля; окончательный выбор только после benchmark на RMX5566.
  - https://github.com/ggml-org/llama.cpp
  - https://github.com/ggml-org/llama.cpp/blob/master/docs/android.md
- **LiteRT-LM**: отдельный backend для совместимых .litertlm моделей/Gemma; не удалять существующие интеграции до сравнения.
  - https://github.com/google-ai-edge/LiteRT-LM
  - https://developers.google.com/edge/litert-lm/android
- **Model Router**: локальная модель по умолчанию; облачные GPT, Claude, Gemini, Grok — опциональные адаптеры с ключами владельца и явным разрешением на передачу данных.
- **Memory/Knowledge**: зашифрованная локальная память, Diary, поиск, история задач и локальная база знаний.
- **Tool Gateway**: реестр навыков и Android API; каждый инструмент объявляет возможности, разрешения, ограничения и тесты.
- **Policy/Consent Gate**: звонки, сообщения, платежи, публикации, удаление данных, установка APK/пакетов и необратимые действия требуют подтверждения владельца.
- **Resource Governor**: ограничение RAM/context/threads, учёт температуры/батареи, отмена задач, выгрузка модели при давлении памяти и безопасное восстановление.
- **Skill/Package Manager**: подписанные .manapack, SHA-256, зависимости, проверка совместимости и транзакционный rollback. APK обновлять только штатным PackageInstaller с подтверждением.

## 4. Системные и пользовательские требования, которые нельзя потерять

Сохранить единый MANA XZ продукт и все ранее перечисленные области: русский голос и аватар; локальная память и офлайн-режим; интернет-исследование и база знаний; Future Updates и контролируемое саморазвитие; Diary; Smart Receptionist (игривый характер, задержка 10 секунд, сводки и неизвестные номера в пределах Android API); Contact Intelligence; Life Manager; Yandex/VK через официальные API; Game Intelligence/Minecraft; часы, наушники и автомобиль через поддерживаемые интерфейсы; облачные AI-провайдеры как опция; единый реестр модулей; отчёт диагностики и обновлений.

Не обещать непрерывную 24/7 работу, root, системные привилегии, чтение произвольных данных или бесшумную установку. Android разрешения, роли, энергосбережение и OEM ограничения остаются действительными. Текущий этап — отдельное приложение поверх Realme UI; системная адаптация откладывается.

## 5. Единая поставка

Целевая пользовательская поставка — один установочный комплект с основным APK, manifest, движком, библиотеками, моделью, голосом, аватаром и модулями. Предпочтительная UX-цель — один APK, который сам обнаруживает и проверяет встроенные ресурсы. До обещания этого формата проверить фактические лимиты PackageInstaller, подпись, ZIP/asset access, извлечение большой модели, свободное место и обновление. Если полная модель не помещается/не читается в одном APK, честно зафиксировать техническое ограничение и использовать согласованный единый контейнер с APK и ресурсами, не выдавая архив за APK.

## 6. Порядок работ

1. Инвентаризировать все существующие inference implementations и владельцев lifecycle; устранить дублирование, не удаляя работающие пути до тестов.
2. Зафиксировать единый InferenceBackend контракт и сохранить обратную совместимость MANA Brain.
3. Реализовать backend adapters для llama.cpp и LiteRT-LM.
4. Собрать одинаковый benchmark harness и измерить GGUF-кандидат и Gemma/LiteRT-LM на реальном RMX5566: cold start, first-token latency, tokens/sec, peak RAM/PSS, температуру, батарею, устойчивость контекста и OOM recovery.
5. Выбрать backend/model по измерениям, а не предположениям.
6. Реализовать Resource Governor, memory/knowledge, tool registry и consent gate.
7. Добавлять исторические модули по одному с честным статусом и тестами.
8. Проверить однофайловую упаковку и штатное обновление на API 29 и API 36; физический тест RMX5566 обязателен.
9. Каждую итерацию — отдельный commit/PR и CI; не сливать main без разрешения.

## 7. Статусы

Использовать только: IMPLEMENTED_AND_TESTED, IMPLEMENTED_NOT_DEVICE_TESTED, PARTIAL, BLOCKED_BY_ANDROID, NEEDS_PROVIDER_KEY, PLANNED. Наличие класса, экрана или документа не доказывает runtime readiness. До физического запуска модели на RMX5566 все результаты локального inference помечать NOT_DEVICE_VERIFIED.
