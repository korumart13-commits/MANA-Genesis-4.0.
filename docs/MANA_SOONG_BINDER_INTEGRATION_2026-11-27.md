# MANA Genesis 4.0 — Soong and Binder integration gate

Date: 2026-11-27

## What was added

- `system/mana/tests/ManaBrainBinderIntegration` is a platform-signed Soong
  `android_test` module. It binds to the installed platform `ManaBrainService`,
  checks the AIDL protocol version and waits for the service to complete the
  `IManaEngineBackend` handshake with the app-owned bridge.
- `tools/run_mana_soong_integration.sh` stages the unsigned Gradle release APK,
  runs Soong's own test suite, builds the interface, platform service, imported app,
  host policy tests and device instrumentation test, then optionally runs the Binder
  test with `atest` on a booted target image.
- `tools/test_mana_soong_integration.sh` and
  `.github/workflows/mana-soong-contract.yml` validate the source-level integration
  contract in ordinary GitHub-hosted CI.

## Run on a real AOSP build host

First complete a full Android 16 AOSP checkout, attach the pinned MANA local manifest,
and make sure the selected product makefile includes
`vendor/mana/genesis/system/mana/mana_product.mk`. The product must install
`ManaBrainService` and the staged `ManaLauncher` app. Obtain the unsigned
`app-release-unsigned.apk` from the successful Gradle release workflow artifact.

Build and run host tests:

```sh
vendor/mana/genesis/tools/run_mana_soong_integration.sh \
  "$ANDROID_BUILD_TOP" "<actual-lunch-target>" \
  /path/to/app-release-unsigned.apk
```

To also run the device-side Binder handshake test, boot an emulator/device image built
with both product packages and run:

```sh
vendor/mana/genesis/tools/run_mana_soong_integration.sh \
  "$ANDROID_BUILD_TOP" "<actual-lunch-target>" \
  /path/to/app-release-unsigned.apk --run-device-tests
```

The test APK is signed with the product platform certificate and requests the same
signature permission as the two services. The test deliberately verifies the actual
cross-process connection and protocol negotiation; it does not claim that a local model
is installed, that inference quality is correct, or that cloud providers are configured.

## What this does not prove

The GitHub workflow is a source-contract check, not a Soong build. The real commands above
have **not yet been executed**, because this repository does not contain a full AOSP
checkout and no verified RMX5566 product target exists. Do not mark the Soong build,
signed certificate comparison, SELinux policy, emulator Binder runtime, or device test
as passed until their actual logs and artifacts exist.

The integration test requires a booted image containing both packages, signed with the
same platform key. A test run on a generic emulator validates the Binder architecture
only; it does not establish RMX5566 compatibility.

SELinux service contexts/domain and least-privilege Binder policy remain a separate
required gate. No image, OTA, boot/recovery partition, or firmware is generated by these
scripts. No RMX5566 flashing is authorized without exact matching firmware, full device
sources, verified partition/AVB metadata, and a tested stock restore route.

## Soong import correctness

The imported launcher is deliberately configured as `android_app_import` with
`presigned: false` and `certificate: "platform"`: Soong signs the unsigned Gradle APK
using the product's platform certificate. The platform Brain service and test APK use
the same certificate. The apps remain non-privileged. This matches the upstream Soong
`android_app_import` contract, which requires exactly one signing mode and signs an
unsigned imported APK when a certificate is specified. See the upstream implementation:
https://android.googlesource.com/platform/build/soong/+/refs/heads/master/java/app_import.go
