# MANA Genesis 4.0 — режим владельца и локального главного узла

Статус: архитектурная спецификация для следующего обновления. Этот документ сам по себе не означает, что функции уже встроены в APK.

## Зафиксированные решения владельца
- Роль в MANA: **Главный разработчик и владелец**.
- Основное устройство: **realme RMX5566** (Android 16, по данным владельца).
- Роль устройства: **MANA Primary Node** — главный локальный узел.
- Сеть: другие устройства подключаются только по явной команде и после одобрения владельца.
- Режим по умолчанию: локальная работа; удалённый доступ из интернета выключен.

## 1. MANA Developer Center
Раздел приложения: **Настройки → MANA Developer Center**.
Показываемые поля: роль владельца, основное устройство, статус сервера, версия приложения, версия схемы данных, отпечаток сертификата подписи, список подключённых устройств.
Функции: сведения о сборке и журналы; управление сервером; доверенные устройства; одобрение и отзыв подключений; резервное копирование; журнал действий владельца.
Роль владельца — прикладная роль MANA. Она не выдаёт Android root, системную подпись, права Device Owner или возможность обходить разрешения ОС.

## 2. Локальный сервер MANA
- Сервер выключен по умолчанию и запускается владельцем вручную.
- Для работы в фоне использовать Android foreground service с постоянным системным уведомлением, с учётом ограничений целевой версии Android.
- Слушать только локальную сеть (LAN); не открывать порт в публичный интернет.
- Не включать UPnP, автоматический проброс портов или скрытый удалённый доступ.
- Интерфейс управления доступен только после аутентификации владельца.

### Протокол подключения устройства
1. Владелец нажимает «Добавить устройство».
2. MANA создаёт одноразовый QR-код/код сопряжения с коротким сроком действия.
3. Второе устройство сканирует код и показывает запрашиваемые сведения и права.
4. Владелец явно нажимает «Разрешить».
5. Устройства устанавливают защищённое соединение с проверкой сертификата/ключа узла.
6. MANA сохраняет отдельный отзывной ключ устройства.
7. Владелец может отключить устройство; его ключ становится недействительным.
Не использовать общий постоянный пароль для всех устройств. Не передавать токены или приватные ключи в логи.

## 3. Минимальная модель разрешений
- STATUS_READ: состояние узла и версия.
- SYNC_SETTINGS: синхронизация явно выбранных настроек.
- SYNC_MEMORY: синхронизация выбранных пользовательских данных только после отдельного согласия.
- SEND_COMMAND: только заранее определённые безопасные команды MANA с проверкой полномочий.
- ADMIN_PAIRING: добавление/отзыв устройств — только на главном узле после подтверждения владельца.
Новые устройства получают минимальные права. Синхронизация памяти и личных данных выключена по умолчанию.

## 4. Хранение и безопасность
- Приватный ключ подписи Android-приложения хранить отдельно, с резервной копией; никогда не помещать его в GitHub или APK.
- Ключи сопряжения хранить в Android Keystore, где это возможно.
- Локальные данные шифровать; секреты не хранить в открытом виде.
- Вести журнал действий: сопряжение, отзыв, экспорт, импорт и изменение разрешений.
- Резервные копии шифровать и проверять на целостность.
- Обновления должны быть подписаны тем же ключом, что и установленная версия, иначе Android не установит их поверх неё.

## 5. Этапы реализации
### A. Следующее Android-обновление
1. Добавить Developer Center как экран приложения.
2. Добавить экран Primary Node и состояние сервера.
3. Реализовать ручной запуск/остановку локального сервиса.
4. Добавить список устройств и одноразовое сопряжение.
5. Добавить подтверждение владельца и отзыв устройств.
6. Покрыть тестами авторизацию, срок действия кода, отзыв ключа и запрет доступа без разрешения.
### B. После тестирования на Realme
- Синхронизация выбранных данных.
- Клиент для компьютера.
- Клиенты для других платформ.
- Облачный relay — только как дополнительный транспорт; он не должен обходить согласие владельца.

## 6. Критерии готовности
- Сервер не запускается самовольно после установки.
- Устройство без одобрения не получает доступ.
- Одноразовый код нельзя использовать повторно или после истечения срока.
- Отозванное устройство теряет доступ.
- Владелец видит активные подключения и может остановить сервер.
- Секреты отсутствуют в логах и репозитории.
- Функции не считаются реализованными, пока не встроены, собраны и проверены на устройстве.

## Важное ограничение текущего этапа
В репозитории сейчас хранится исходный ZIP проекта и workflow сборки. Исходные Android-файлы внутри ZIP не представлены отдельными файлами Git. Поэтому эта спецификация добавляется как отдельный архитектурный документ; она ещё не является изменением установленного APK. Для реальной интеграции нужно обновить исходный проект внутри ZIP и выполнить новую успешную облачную сборку.
