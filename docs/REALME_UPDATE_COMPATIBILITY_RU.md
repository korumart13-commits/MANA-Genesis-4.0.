# MANA Genesis 4.0 — модель обновления для realme RMX5566RU

## Цель

Сделать установку и сопровождение MANA максимально похожими на штатное обновление телефона: один понятный пакет, предварительная проверка модели и версии, проверка контрольных сумм, журнал результата, сохранение пользовательских данных и возможность отката компонентов MANA.

Этот документ описывает безопасную архитектуру для текущего устройства владельца:

- модель/вариант: RMX5566RU, кодовое имя RE645F;
- заявленная база: Android 16 / API 36;
- исходный fingerprint: realme/RMX5566RU/RE645F:16/BP2A.250605.015/V.2f025ac-8895bb-9a8318:user/release-keys;
- OTA-профиль из диагностики: RMX5566_11.F.03_2030_202610170441;
- загрузчик: locked; AVB: green; A/B slots; active slot при последней диагностике: _a.

Значения выше являются целевыми ограничителями сборки, а не доказательством того, что пакет уже установлен или что OEM-разделы доступны для изменения.

## Два независимых контура обновления

### Контур A — обновление Realme

1. Проверять обновления через штатные «Настройки → Обновление ПО» и штатный сервис Realme.
2. При локальном обновлении использовать только пакет, опубликованный Realme для точного RMX5566RU/RE645F и соответствующего региона/ветки прошивки.
3. Не переименовывать и не перепаковывать OEM OZIP/OTA.
4. Не добавлять APK, модель или файлы MANA внутрь OEM-пакета: любое изменение нарушит OEM-подпись/проверку целостности.
5. Не понижать версию и не смешивать пакеты разных SKU, регионов, SoC или fingerprint.
6. MANA Update Bridge только открывает штатный экран обновления Realme; он не получает права на запись разделов и не имитирует OEM updater.

### Контур B — обновление MANA

Один MANA ZIP содержит пользовательский APK, офлайн-модель (если включена в выпуск), каталог функций, архитектуру, исходный архив, лицензии, инструкции и метаданные релиза.

Перед установкой MANA-компонентов проверяются:

- ожидаемый package ID и target device;
- модель RMX5566RU/RE645F и Android API;
- совместимость минимальной/максимальной версии MANA;
- размер каждого обязательного файла;
- SHA-256 каждого файла и ZIP;
- подпись собственного канала обновлений MANA;
- наличие достаточного свободного пространства;
- резервная копия пользовательского состояния MANA.

Обычный Android APK устанавливается только через подтверждение владельца. Назначение MANA приложением HOME выполняется через системный диалог Android. Импорт большой локальной модели подтверждается пользователем и проходит проверку SHA-256.

## Поведение, похожее на штатный updater

- Единая карточка релиза: версия, дата, устройство, размер, список изменений и известные ограничения.
- Состояния: «проверка устройства», «проверка пакета», «готово к установке», «ожидает подтверждения», «установка приложения», «проверка после установки», «успешно» или «ошибка».
- Проверка целостности до любых действий.
- Никаких скрытых установок, фонового назначения HOME или принудительной перезагрузки.
- Сохранение зашифрованной памяти/дневника MANA и миграция схемы данных между версиями.
- Если проверка не пройдена — остановиться без изменения телефона и показать причину.
- Хранить журнал версий MANA, контрольные суммы и результат последней проверки.
- Отдельно показывать статус официальной прошивки Realme и статус пользовательских компонентов MANA; не смешивать их в один ложный статус «обновлена прошивка».

## Почему сейчас нельзя создать настоящий OEM OTA с MANA внутри

Настоящий Android OTA создаётся из device-specific target-files, partition metadata, boot/vendor/system/product images и подписывается ключами, которым доверяет установленная система/recovery/boot chain. Для A/B-устройств также необходимы точная конфигурация update_engine, payload metadata и OEM-поддержка. Тестовый ключ AOSP не заменяет закрытый ключ Realme.

В текущем проекте отсутствуют подтверждённый полный набор исходников и бинарных vendor-компонентов для точной ревизии RE645F, воспроизводимая device-specific сборка всех разделов и OEM release signing key. Загрузчик устройства по диагностике заблокирован, AVB green. Поэтому MANA ZIP не должен записывать boot/system/vendor/vbmeta или объявлять себя OZIP/OTA.

## Дорожная карта до более глубокой интеграции

1. Собирать и проверять MANA как отдельный пользовательский слой поверх неизменённой Realme UI.
2. Получить и зафиксировать официальные источники именно для RMX5566RU/RE645F: точную версию firmware, kernel source/config, device tree, vendor blobs, VINTF/HAL и partition metadata.
3. Проверить лицензии, воспроизводимость и соответствие исходников конкретному fingerprint.
4. Создать отдельную экспериментальную AOSP product/ROM ветку для устройства; не выдавать её за OEM Realme firmware.
5. Собрать все разделы и OTA payload для тестового устройства с собственными тестовыми ключами только после подтверждения полной аппаратной совместимости и наличия поддерживаемого способа разблокировки/установки.
6. Отдельно тестировать recovery, AVB, rollback protection, слот A/B, сохранность данных, аварийный возврат и реальное восстановление.
7. Публиковать release только после прохождения тестов; для штатного Realme updater OEM-подпись может выдать только Realme или субъект, чьи ключи уже доверены устройством.

## Границы безопасности

Запрещено обходить проверку подписи, AVB, rollback protection, загрузчик, SELinux или Android sandbox; подменять fingerprint; прошивать чужой OZIP; угадывать разделы или выполнять запись в блочные устройства. Никакая ошибка проверки не должна приводить к попытке «продавить» установку.
