# Совместная работа ChatGPT и Claude над MANA Genesis 4.0

**Канонический репозиторий:** https://github.com/korumart13-commits/MANA-Genesis-4.0.  
**Главная ветка:** `main`.  
**Цель:** передавать контекст и результаты через GitHub, не отправляя Claude ZIP на 2,78 ГБ.

## 1. Как обмениваться контекстом
- Источник истины — файлы репозитория и история Git, а не пересказ в чате.
- Claude читает `CLAUDE.md` и перечисленные там документы.
- ChatGPT и Claude публикуют независимые отчёты в `ai-collaboration/inbox/`.
- Обсуждение не требует скачивать Gemma или полный Actions artifact. Для проверки модели достаточно метаданных, контрольной суммы и CI-логов.
- Ни один агент не должен считать, что другой агент уже выполнил действие, пока нет коммита, PR или проверяемого CI-результата.

## 2. Разделение ролей
- **ChatGPT:** ведёт основную работу с владельцем, формирует задачи, проверяет архитектуру, просматривает изменения Claude, интегрирует одобренные решения.
- **Claude:** независимый технический аудитор и автор ограниченных PR; ищет противоречия, пробелы, ошибки сборки, угрозы безопасности и предлагает проверяемые исправления.
- **Владелец:** утверждает изменения с влиянием на данные, безопасность, платежи, системные разделы, загрузчик и прошивку. Никаких скрытых действий.

## 3. Правила Git
1. Не вносить изменения напрямую в `main`.
2. Каждый агент создаёт отдельную ветку: `chatgpt/<task>` или `claude/<task>`.
3. Изменения — через Pull Request в `main`.
4. Один PR — одна логическая задача; не смешивать форматирование, рефакторинг и функциональные изменения.
5. Перед слиянием проверить diff, тесты, workflow и влияние на существующие функции.
6. Не перезаписывать чужие отчёты; использовать уникальные имена с датой.
7. Не добавлять API-ключи, токены, пароли, подписи, личные данные и бинарные OEM blobs неизвестного происхождения.

## 4. Формат отчёта
Каждое утверждение помечать:
- **ПРОВЕРЕНО** — есть путь/строка, тест или ссылка на CI.
- **ВЫВОД** — логическое заключение из проверенных фактов.
- **ПРЕДЛОЖЕНИЕ** — ещё не реализовано.
- **НЕИЗВЕСТНО** — данных нет.

Отчёт должен включать цель, просмотренные файлы, найденные проблемы, приоритет, доказательства, тесты, риски, блокеры и конкретный следующий шаг.

## 5. Ключевые технические границы
- APK, приложение/лаунчер, AOSP-модуль, полный AOSP build и прошиваемый ROM — разные результаты.
- Self-Build означает адаптивный агент: диагностика, согласия, проверка источников, подготовка открытых компонентов, изолированная сборка/тесты и отчёт готовности. Это не готовая прошивка.
- APK не может сам выдать себе системные привилегии, создать закрытые драйверы производителя, разблокировать загрузчик, обходить Verified Boot или безопасно прошить разделы.
- Не использовать ядро, vendor blobs, DTB/DTBO или firmware от похожего устройства.
- Firmware readiness остаётся BLOCKED/NOT_READY, пока не доказаны точная device tree, совместимые OEM kernel/vendor, VINTF/HAL, разметка разделов, AVB/signing и проверенный путь восстановления.
- Все разрушительные и критические действия требуют отдельного явного подтверждения владельца.

## 6. Первое задание Claude
Сделать независимый read-only аудит репозитория: реализовано ли то, что описано; что только документировано; состояние CI; реальная готовность APK; ограничения RMX5566RU; пробелы безопасности и тестирования; десять следующих задач по приоритету. Результат положить в `ai-collaboration/inbox/claude-audit-YYYY-MM-DD.md`. Не скачивать многогигабайтный архив и не изменять `main`.

## 7. Проверка ChatGPT перед интеграцией
ChatGPT проверяет каждый PR: соответствие требованиям владельца, diff, корректность API/версий, тесты, секреты, разрешения, firmware gates, отсутствие регрессий. Не принимать выводы только на основании описания Claude — смотреть реальные изменения и CI.
