# MANA Genesis 4.0 — установка без Termux (архитектура)

Дата проверки: 2026-11-27

## Цель UX

Пользователь устанавливает один MANA APK обычным способом. Внутри приложения есть мастер:
1. Проверка модели/сборки/ABI/API/слота/Verified Boot и доступных системных возможностей через публичные Android API.
2. Запрос только необходимых runtime-разрешений в момент использования; отказ или недоступность явно отражаются в отчёте.
3. Сбор read-only диагностики, проверка подписи и контрольных сумм входных пакетов.
4. Получение только совместимого, подписанного и проверенного OTA-пакета из доверенного источника.
5. Передача установки штатному системному механизму только если ОС действительно предоставляет приложению соответствующие полномочия.
6. Проверка результата после перезагрузки: fingerprint, версия, активный слот и статус загрузки, если доступны.

Никакого Termux, shell-команд от пользователя или ручного редактирования файлов.

## Что реально предоставляет Android

### A/B и Virtual A/B

AOSP описывает OTA через update_engine. Для A/B обновления пакет применяется к неактивному слоту, проверяются записанные разделы, затем загрузчик пробует новый слот. При неудачной загрузке предусмотрен откат на прежний рабочий слот. Это не универсальный API для произвольного стороннего APK: клиент обновления и update_engine должны быть интегрированы и разрешены системной сборкой.

Официальные материалы:
- https://source.android.com/docs/core/ota/
- https://source.android.com/docs/core/ota/ab
- https://source.android.com/docs/core/ota/ab/ab_implement

### DevicePolicyManager

Android API DevicePolicyManager.installSystemUpdate существует (API 29+), но доступен Device Owner или Profile Owner управляемого профиля организации. Это не обычное runtime-разрешение, которое любой APK может запросить. Даже успешный вызов означает установку системного OTA, а не создание или подпись новой прошивки. После перезагрузки приложение должно проверить фактическую версию.

Официальные материалы:
- https://developer.android.com/reference/android/app/admin/DevicePolicyManager#installSystemUpdate(android.content.ComponentName,android.net.Uri,java.util.concurrent.Executor,android.app.admin.DevicePolicyManager.InstallSystemUpdateCallback)
- https://developer.android.com/work/dpc/system-updates

## Обязательные ограничения RMX5566RU

Текущий известный профиль устройства указывает на заблокированный загрузчик и Verified Boot green. До повторного read-only подтверждения считать это исходным ограничением. Обычное приложение не может снять OEM-блокировку загрузчика, подписать системные разделы ключом производителя или обойти AVB.

Для кастомной MANA ROM всё ещё требуются подтверждённые именно для RMX5566RU:
- device tree и product configuration;
- исходники соответствующего kernel и конфигурация сборки;
- vendor blobs/firmware с подтверждённым происхождением и лицензией;
- VINTF/HAL и совместимость vendor/system;
- partition map, dynamic partitions и boot/recovery layout;
- стратегия AVB, ключи подписи и поддерживаемый способ восстановления stock firmware;
- OTA payload, подписанный ключами, которым доверяет целевая цепочка загрузки.

Нельзя использовать образы от похожих realme-моделей или других устройств с тем же названием SoC.

## Автоматические этапы без пользователя

MANA может автономно выполнять: локальную диагностику в пределах API, сверку публичных источников, проверку хешей и подписей, сборку исходников на доступном CI/build worker, статические проверки, unit tests, APK/OTA packaging, формирование отчётов и подготовку обновления.

MANA не должна автономно выполнять без отдельного подтверждения: разблокировку загрузчика (обычно стирает данные), отключение Verified Boot, изменение разделов, установку неподтверждённого OTA, сброс данных или необратимую прошивку. Это не вопрос интерфейса — такие операции меняют доверенную цепочку загрузки и могут сделать телефон не загружаемым.

## Критерии допуска к установке

Установщик обязан остановиться и показать BLOCKED, если хотя бы одно условие не выполнено:
- exact product/device fingerprint подтверждён;
- пакет предназначен именно для RMX5566RU и текущей версии/слота;
- криптографическая подпись и хеш пакета проверены;
- OTA совместим с текущим source build и partition layout;
- системный update path доступен и подтверждён;
- сохранён проверенный путь восстановления stock firmware.

Никаких fallback-команд для прямой записи block devices из APK.

## Статус реализации

Этот документ задаёт целевую архитектуру UX без Termux и инженерные gates. Сам по себе он не добавляет APK-код для установки OTA и не означает, что RMX5566RU уже принимает сторонние OTA. Следующий кодовый этап — добавить в MANA app capability probe для DevicePolicyManager/system updater, собрать результаты в экран Firmware Installation, а затем реализовать только тот путь, который реально доступен на устройстве.
