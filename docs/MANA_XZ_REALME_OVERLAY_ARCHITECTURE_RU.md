# MANA XZ — архитектура обновления поверх Realme

Статус: проектное решение / не готовая прошивка. Целевое устройство: realme C85 4G, RMX5566, Android 16. Перед любым системным изменением требуется повторная проверка точного SKU, build fingerprint, ABI, Treble/VNDK, AVB, разделов и доступности разблокировки загрузчика.

## 1. Принцип

MANA XZ развивается как совместимый слой над установленной Realme UI, а не как новая ОС с нуля. Первый пользовательский релиз — подписанный APK + проверяемый пакет обновления MANA. Он не перепрошивает boot/system/vendor и не удаляет Realme UI. Системные расширения (RRO, SystemUI, framework, привилегированные службы) выделяются в отдельный device-specific этап и включаются только при наличии корректной подписи/привилегий и проверенного способа восстановления.

## 2. Основа из открытых проектов

- AOSP Runtime Resource Overlays (RRO): только замена существующих ресурсов; не подменяет код приложений и не даёт обычному APK системные привилегии. Документация: https://source.android.com/docs/core/runtime/rros
- Google LiteRT-LM: локальный inference runtime для Android и других платформ; использовать официальный Kotlin/Android API и тесты. Репозиторий Apache-2.0: https://github.com/google-ai-edge/LiteRT-LM
- Google AI Edge LiteRT samples: образцы Android-интеграции Gemma 4 E2B, CPU/GPU fallback и импорта модели: https://github.com/google-ai-edge/litert-samples
- AOSP Launcher3 / Lawnchair 16: ориентир для домашнего экрана и launcher UX; не подменять им системный интерфейс целиком. Перед заимствованием кода отдельно проверить лицензию конкретной ревизии: https://github.com/ryancwalsh/android_launcher_lawnchair
- Jarvis Android assistant (MIT): ориентир по голосовому циклу, локальному wake-word/STT и адаптерам облачных провайдеров; код переносить только после аудита зависимостей, разрешений и лицензии: https://github.com/judejulius/jarvis

Сторонние проекты не копируются вслепую. Для каждого импортируемого компонента фиксируются upstream commit, лицензия, изменения, notices и тесты.

## 3. Слои

### A. MANA XZ App (без root)
- Один основной APK: Launcher/дашборд, MANA Brain UI, настройки, аватар, голосовой диалог, отчёты, импорт пакетов.
- MANA Brain: единый планировщик задач и маршрутизатор инструментов; локальная модель и подключаемые облачные провайдеры.
- Локальная память: Room/SQLite + файлы в приватном хранилище приложения; шифрование ключом Android Keystore; экспорт/импорт по Storage Access Framework.
- Голос: foreground service только с видимым уведомлением и разрешениями; wake-word/STT/TTS адаптеры с выключателями приватности.
- Управление телефоном: только публичные Android API, роли/разрешения, intents, NotificationListenerService, AccessibilityService (только после явного включения пользователем), Companion Device APIs и доступные системные роли.
- Фоновые задачи: WorkManager/JobScheduler для отложенных задач; постоянная 24/7 работа не обещается и зависит от Android 16, Realme battery manager, разрешений и состояния устройства.

### B. MANA Update / Package Manager
- Подписанные .manapack пакеты: manifest, версия, совместимость, зависимости, SHA-256 каждого payload, подпись ECDSA.
- Проверка до установки: подпись по закреплённому публичному ключу, хеши, размеры, traversal/duplicate-entry защита, API/модель устройства, свободное место и зависимости.
- Установка транзакционная в приватное хранилище приложения; при любой ошибке восстанавливается предыдущая версия.
- APK-обновления устанавливаются только через Android PackageInstaller с подтверждением пользователя; .manapack не может незаметно устанавливать APK или системные приложения.
- Секретный ключ подписи никогда не включается в APK или репозиторий.

### C. Device integration (только после диагностики)
- RRO для ограниченных ресурсов, если целевой пакет предоставляет overlayable ресурсы и устройство разрешает установку/активацию.
- Quick Settings/SystemUI, boot animation, системные приложения и framework-службы — только как часть корректно собранного device-specific system image либо подписанного системного пакета с соответствующими привилегиями. Обычный APK этого сделать не может.
- Не использовать случайный GSI как «универсальный патч». GSI требует unlocked bootloader, Treble compliance и проверенного восстановления; неподходящий образ может сделать устройство не загружаемым: https://developer.android.com/topic/generic-system-image

## 4. Реестр возможностей MANA

Каждый пункт имеет один из статусов: IMPLEMENTED_AND_TESTED, IMPLEMENTED_NOT_DEVICE_TESTED, PARTIAL, BLOCKED_BY_ANDROID, NEEDS_PROVIDER_KEY, PLANNED. Статус нельзя повышать без теста и доказательства.

- MANA Brain: диалог, планирование, вызов инструментов, журнал решений, подтверждения опасных/необратимых действий.
- Локальный интеллект: LiteRT-LM + выбранная Gemma-модель; проверка целостности, CPU fallback, оценка памяти/нагрева; без модели показывать честный режим «локальная модель не установлена».
- Облачные модели: OpenAI, Anthropic, Google Gemini, xAI Grok — независимые адаптеры; ключи хранятся защищённо и задаются владельцем; облако опционально.
- Память и Diary: локальные записи, поиск, экспорт, удаление и настройка срока хранения.
- Интернет-исследование и обучение: получение источников, проверка ссылок/дат, локальная база знаний; не изменять исполняемый код без тестов и согласия владельца.
- Future Updates: сбор голосовых идей, backlog, планирование, сборка, тестирование, отчёт и откат.
- Launcher/System UI: главный экран MANA, карточки модулей, панель управления в пределах доступных Android API.
- Аватар и голос: постоянный образ персонажа, меняемые аксессуары/одежда, русская озвучка, прерывание речи и пользовательские настройки.
- Smart Receptionist: задержка ответа 10 секунд, игривый стиль, сводки, неизвестные номера; фактическая автоответная функция зависит от роли dialer/call screening и разрешений Android/оператора.
- Contact Intelligence и Life Manager: только после явных разрешений на контакты/календарь/уведомления; действия подтверждаются.
- Yandex/VK: официальные API/SDK, отдельные адаптеры и проверка доступности; не обходить авторизацию.
- Game Intelligence/Minecraft: отдельный безопасный модуль; не обещать управление игрой без поддерживаемого API/доступности.
- Часы, наушники, автомобиль: Companion Device/Bluetooth/официальные интерфейсы; совместимость проверяется для каждой модели.

## 5. План поставки

1. Инвентаризация текущего репозитория и фиксация матрицы функций/статусов.
2. Исправление и тестирование .manapack verifier/transaction rollback/dependency resolution; закрепление тестового и production trust keys.
3. Рабочий APK shell: onboarding, launcher, MANA Brain UI, private storage, permission dashboard, diagnostics.
4. Реальный LiteRT-LM inference на совместимом Android build; проверка модели на RMX5566 отдельно от CI.
5. Голос, аватар, память, инструменты и модули — по одному, с unit/instrumentation/device tests.
6. OTA-like подписанные обновления приложения и модулей с rollback.
7. Только затем — исследование системного слоя RMX5566: Treble/VNDK, AVB, partitions, bootloader unlock, stock restore package, kernel/vendor/device tree. Без подтверждённого recovery-плана прошивка не создаётся и не устанавливается.

## 6. Критерии готовности

- Не называть сборку полноценной, пока нет реального inference и smoke/device tests на RMX5566.
- Не заявлять, что все исторические функции работают, если часть зависит от API-ключей, ролей, разрешений, внешних устройств или системной подписи.
- Любые платежи, звонки/сообщения, удаление данных, установка обновлений прошивки и другие значимые действия требуют явного подтверждения владельца.
- Обновление должно иметь проверку подписи, хешей, совместимости, резервирование состояния, rollback и понятный журнал.
- Сохранять исходную Realme UI и предоставить документированный путь восстановления до любых системных экспериментов.
