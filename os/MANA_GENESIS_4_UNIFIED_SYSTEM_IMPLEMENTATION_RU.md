# MANA Genesis 4.0 — единая система и путь установки (RU)

Дата: 2026-11-26  
Цель: realme RMX5566RU / RE645F, Android 16, Qualcomm SM6225 (bengal).

## Решение по продукту

Создаётся одна система MANA Genesis 4.0 с единым MANA Brain. Это не набор независимых приложений. MANA Brain — системный оркестратор; MANA OS — Android-платформа, интерфейс, службы и политика безопасности, которыми он управляет. Companion APK остаётся временным способом запуска локального LiteRT-LM runtime до переноса провайдера внутрь системного образа.

Приоритет интерфейса: собственная MANA Desktop/Home с оконной моделью, панелью задач, меню приложений, центром уведомлений/быстрых настроек, файловым менеджером, настройками и плавающим аватаром. Визуальный ориентир — удобство настольной ОС Windows, но дизайн, название и компоненты остаются оригинальными MANA. Это Android-совместимая оболочка, не Windows и не запуск Windows-программ.

## Единая архитектура

1. **MANA Brain Core** — единый API намерений, планирования, capability registry, памяти и маршрутизации моделей.
2. **MANA Brain Service** — Android Binder/AIDL системная граница; проверяет подпись клиента, разрешения, риск операции и подтверждение владельца.
3. **Inference providers** — локальный LiteRT-LM/Gemma как offline-first провайдер; облачные GPT, Claude, Gemini, Grok и Yandex подключаются отдельно, по явному согласию и с ключами в Android Keystore.
4. **MANA System UX** — Launcher/Desktop, Assistant Avatar, Settings, Control Center, notifications/lockscreen/SystemUI. Привилегированные поверхности собираются в платформу; обычный APK не объявляется заменой SystemUI.
5. **MANA Services** — encrypted memory, Diary, Life Manager, Adaptive Intelligence, Update, Device Intelligence и остальные модули. Каждый модуль объявляет зависимости, разрешения, уровень риска и состояние реализации.
6. **Compatibility layer** — ART, Package Manager, Binder, Android permissions, HAL/VINTF и OEM vendor stack сохраняются до тех пор, пока точная замена не доказана тестами.
7. **MANA Update** — проверка метаданных, подписи и хэшей; staged install; проверка результата; журнал и rollback. Brain не может отключить проверку подписи или самостоятельно подтвердить опасное обновление.

## Единый сценарий загрузки и запуска

- Android init запускает только проверенные системные службы.
- MANA Brain Service стартует после готовности Binder и зависимостей.
- Служба проверяет доступность локального inference provider и регистрирует capabilities.
- MANA System UX поднимает рабочий стол, панель задач, статус/уведомления и Avatar surface.
- Если локальная модель недоступна, система честно показывает статус провайдера; облако не включается скрытно.
- При сбое MANA UX Android должен оставаться восстанавливаемым через штатный системный launcher/recovery path.

## Формат установки: требование и реальность

Целевой пользовательский формат — единый подписанный пакет обновления MANA для A/B устройства, с проверкой payload, корректными metadata, совместимыми partition operations и подтверждённым rollback. Внутренний формат может быть AOSP OTA payload/target-files, но это не означает совместимость со штатным Realme Updater.

Пока загрузчик заблокирован и AVB доверяет OEM-ключам, MANA-подпись не принимается штатным Realme Recovery/Updater. Нельзя переименовать или переподписать OEM OTA и выдавать её за MANA. До подтверждения официально поддерживаемого OEM механизма установка возможна только через документированный и проверенный путь для разблокированного устройства — если такой путь доступен для конкретного SKU/региона. Никакой автоматической разблокировки, стирания данных или прошивки в CI.

## План реализации в репозитории

### Этап 1 — единый контракт (текущая работа)
- Свести system modules, Companion runtime и JVM core к одному API и одной модели capability.
- Проверить отсутствие дублирующих реализаций MANA Brain.
- Зафиксировать IPC fallback только как временный переходный адаптер.
- Обновлять IMPLEMENTATION_LEDGER.md по фактическим тестам, не по наличию экранов.

### Этап 2 — полноценная Android-платформа
- Получить полный pinned AOSP 16 source checkout.
- Подготовить точный RE645F product/device tree, vendor/odm blobs, VINTF, init, fstab, SELinux, overlays и partition sizes.
- Воспроизвести штатную сборку kernel 5.15.197 до любых изменений.
- Перенести MANA Brain Service и локальный inference provider в system/system_ext/product согласно проверенным Soong modules.
- Реализовать платформенный MANA SystemUI и Desktop/Home; сохранить штатный путь восстановления.
- Собрать reproducible target-files и образы только после зелёных device gates.

### Этап 3 — OTA и проверка
- Создать OTA из MANA target-files официальными AOSP releasetools.
- Подписать release-ключами проекта; проверить payload signature, metadata, rollback index, A/B post-install и размер разделов.
- Проверить установку/откат на тестовом устройстве с тем же SKU и известным stock restore package.
- Пройти тесты экрана, touch, камеры, аудио, модема/IMS, Wi-Fi, Bluetooth, GPS, датчиков, зарядки, сна, шифрования и обновления.
- Только затем публиковать как installable MANA firmware candidate.

## Безопасный запасной вариант интерфейса

Если полный ROM порт пока невозможен, собирается **MANA Desktop** как Android HOME/assistant APK: оконоподобный рабочий стол, taskbar, Start-подобное меню, виджеты, приложения Android, файловый интерфейс и единый вход к MANA Brain. Он устанавливается обычным APK и выбирается владельцем как HOME. Это не перепрошивка, не системный SystemUI и не замена ядра; он позволяет пользоваться цельным интерфейсом без предпросмотра в отдельном макете, но Android остаётся базовой ОС.

## Текущие блокирующие условия для RMX5566RU

- AOSP manifest pin сам по себе не означает, что исходники AOSP уже синхронизированы.
- Доступный kernel source — только кандидат: известная версия 5.15.180 не совпадает с устройством 5.15.197.
- Точный device tree, vendor blobs, DTBO, VINTF, partition metadata и проверенная цепочка подписи/восстановления не подтверждены.
- Поэтому boot/vendor_boot/dtbo/vbmeta/super и OTA остаются запрещёнными к сборке для установки до снятия этих блокировок.

## Критерий готовности

Система называется прошивкой, пригодной к установке, только если AOSP и точные device sources воспроизводимо собираются, все образы и OTA криптографически проверяются, аппаратные тесты проходят, установка и возврат на точную стоковую версию проверены. До этого артефакты называются исходниками, прототипом или Android APK — без ложной маркировки «прошивка».
