# Канал обновлений MANA Genesis 4.0

## Отдельная идентичность обновления

MANA использует собственный канал `com.mana.genesis.system` и независимый счётчик:
- первая поставка: `MANA +1`, `version_code=1`;
- следующая поставка MANA: `MANA +2`, `version_code=2`;
- далее счётчик растёт только внутри канала MANA.

Это **не** изменение версии Realme UI, Android build ID или OTA-метаданных OEM. Оригинальная прошивка остаётся идентифицирована своим исходным fingerprint. MANA хранит его как базовую совместимость, а не переписывает. Поэтому Android/Realme updater и MANA updater не должны сравнивать версии между собой.

Версия MANA сравнивается только с предыдущей версией MANA: например, установленная MANA 0 допускает MANA +1, а уже установленная MANA +1 отклонит повторную установку MANA +1. Версия Realme/Android не участвует в этом сравнении и не переписывается.

## Что проверяет валидатор

`tools/mana_update_manifest.py` проверяет отдельный канал, модель RMX5566RU, устройство RE645F, Android API 36, точный fingerprint базовой сборки, допустимые типы пользовательских артефактов, HTTPS, размер, SHA-256 и подпись Ed25519 манифеста.

Допустимые типы артефактов на текущем этапе: `companion_apk`, `module_bundle`, `model_bundle`. Образы boot/vendor_boot/dtbo/vbmeta/super и произвольные прошивочные разделы намеренно не допускаются этим каналом. Валидатор проверяет манифест; загрузчик обязан отдельно сверять SHA-256 скачанного файла, а установщик — подпись самого APK/пакета и допустимый способ установки.

## Саморазвитие MANA

Целевой цикл:
1. MANA Brain формулирует задачу и план изменения.
2. Изолированный рабочий каталог получает копию исходников и нужные тестовые данные.
3. Агент предлагает патч только в разрешённых каталогах MANA; системные и OEM-файлы read-only.
4. Автоматически запускаются форматирование, компиляция, unit/integration/security tests и проверка лицензий зависимостей.
5. Неудачный патч откатывается; успешный сохраняется как кандидат с diff, журналом и тестовыми результатами.
6. Release builder собирает воспроизводимые APK/модули, вычисляет хеши и подписывает манифест ключом выпуска MANA.
7. Устройство проверяет подпись, версию, fingerprint и целевую модель до установки. Неудачная активация должна возвращать предыдущую рабочую версию.

MANA сможет самостоятельно анализировать, менять, тестировать и выпускать **собственные исходники и модули** в этой песочнице. Изменение работающего системного раздела, ядра, AVB, SELinux, модема или OEM-драйверов не является обычной операцией самообновления и требует отдельной проверенной сборки/цепочки доверия.

## Текущий статус

Добавлен проверяющий код и unit-тесты для подписанного MANA-манифеста. Это фундамент независимого канала, не готовый установщик, не OTA и не прошивка. Для установки APK/модулей ещё нужен Android-side updater, release key в защищённом хранилище и тесты на устройстве. Для настоящего системного обновления MANA внутри собственной ROM дополнительно нужны подтверждённые device tree, точные kernel/vendor/HAL/partition/AVB inputs и сборка полного Android 16 продукта.

## Запуск тестов

```sh
python -m pip install cryptography
python -m unittest discover -s tools/tests -p 'test_mana_update_manifest.py' -v
```

Ключи выпуска не хранятся в репозитории. Тестовые ключи создаются только в памяти.
